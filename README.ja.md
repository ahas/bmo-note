# bmo-note

プラットフォームの編集可能なノートを一つのサービスとして提供します。各ノートは Nuxt UI のエディターのリッチテキスト
ドキュメントで、TipTap JSON として独自のメタデータとともにユニットの SQLite ストアに保存されます。ノートは Web
コンソールのサイドバーから作成・編集・検索します。`[[` または `@` でノート同士をリンクでき、ノートをリンクしている
ノートがその下に一覧され、語句にコメントスレッドを付けられ、ノートについて AI に尋ねたり相談したりできます。
ノートを表示するコンソールプラグインバンドルもこのリポジトリからビルドされます。`docs/design.md` はこのサービスが
何であるか、`docs/api.md` はその境界を記しています。

## テスト

`cargo test`(testbed 経由)は、クレートの唯一のハーネス `tests/main.rs` を一時的な SQLite ファイルとループバック
ポートの上で実行します。対象は次のとおりです。各アカウントのノートの書き込み、読み取り、保存、競合、ゴミ箱への移動、
復元、完全削除(`notes.rs`)、サービスがドキュメントから読み取る内容(`document.rs`)、ノートのドキュメントに付随する
もの — ドキュメントの内容、リンク、アイコン、コピー(`beside.rs`)— とノートが持つ画像(`blobs.rs`)、コメント
スレッド(`comments.rs`)、リンクやメンバーで共有されるノート(`sharing.rs`)、各読者自身のピン留めと閲覧履歴
(`own.rs`)、検索(`search.rs`)、書き込みが発行するストリーム(`events.rs`)、サービスが提供するコンソール画面と、
取り込んだリリース上で bmo-ui 自身の読み取りを通して読むそのマニフェスト(`console.rs`)、そしてユニット自身の
リポジトリ検査(`repository.rs`)です。コンソールバンドルの検査は `client/` 内の `bun run check` で、インストール、
型検査、バンドルのビルド、ユニットテストを行います。`client/tests/browser/` のブラウザーテストはスイートの
ブラウザーレーンで実行されます。

## 構成

| フォルダー | 内容 |
|---|---|
| `src/` | サービスとそのコマンド。ルート、ノートストア、ドキュメントの読み取り、コメント、イベントリング、コンソール画面の宣言 |
| `client/` | 独立したプロジェクトであるコンソールプラグインバンドル |
| `deploy/` | サービスのユーザーユニットと、デプロイが公開するアプリ宣言 |
| `tests/` | クレートの唯一のテストハーネスと、それが使う代役 |
| `docs/` | サービスが何であるかとその境界を定める正式な文書 |

ルートには Cargo のマニフェストとロックファイル、`testbed.toml`、`rustfmt.toml`、`settings.toml`(バイナリに
組み込まれた既定値)、`CLAUDE.md`、`PERSONAL-DATA.md`、ライセンスがあります。

## コマンド

- `bmo-note serve` はストアを開き、停止を指示されるまでルートに応答します。
- `bmo-note health` は設定が指すサービスが準備完了と応答すれば 0 で終了します。
- `bmo-note console-reach` は、デプロイのコンソール検査のために、コンソールがサービスに届く方法を出力します。

設定は、バイナリに組み込まれた `settings.toml`、次にリリースの横にあるデプロイの `settings.toml` と
`settings.local.toml`(データルートの `env/note.toml`)、最後に環境の `BMO_NOTE_<TABLE>__<KEY>` の順に読まれます
(`docs/api.md`、「Settings」)。
